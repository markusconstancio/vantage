## Footprint Summary

- **Identity/Accounts:** the reused handle `@jrivera_codes` ties a code-host
  profile, a microblog, and forum accounts into one identity, with real name
  and city in a bio.
- **Contact:** work email format and a personal phone number are exposed via an
  old resume PDF that is publicly indexed.
- **Employment:** employer and role are public, and the email format is known.
- **Pretext material:** dog's name ("Biscuit"), home climbing gym, and
  photography hobby are all public.

## Attack Scenarios

1. **Credential stuffing / account takeover (most likely).** Passwords were
   exposed in DemoForum 2019, and the same handle is reused widely. An attacker
   replays the breached password against the subject's other accounts.
   *Enabled by:* breach passwords + credential reuse.

2. **Spear-phishing with an internal pretext.** Knowing the employer, role, and
   email format (`first.last@northwind.example`), an attacker crafts a
   convincing IT or recruiter lure referencing the subject's actual work.
   *Enabled by:* employment exposure + email format.

3. **Security-question / password guessing.** Pet name and hometown are common
   answers to account-recovery questions.
   *Enabled by:* interests + identity exposure.

4. **Vishing / SIM-swap groundwork.** The exposed phone plus employer supports a
   helpdesk-impersonation pretext.
   *Enabled by:* contact exposure + employment.

## Remediation (ranked by impact per effort)

1. **Enable MFA everywhere**, prioritising email and the code host — kills the
   credential-stuffing path even if a password leaks. *(High impact, low effort)*
2. **Rotate all reused passwords via a password manager**, unique per site.
   *(High impact, low effort)*
3. **Remove the resume PDF** (or the phone number from it) from public indexing;
   request cache removal. *(Medium impact, low effort)*
4. **Split identities:** stop reusing one handle across personal and
   professional accounts. *(Medium impact, medium effort)*
5. **Tighten profile visibility** and remove pet/location tags used as
   pretext/recovery answers. *(Medium impact, low effort)*
6. **Set recovery answers to random values** stored in the password manager,
   not real facts. *(Medium impact, low effort)*

## Re-score target

Completing items 1–3 would drop breach-exposure and credential-reuse impact
substantially, moving the subject from **High (73)** into the **Moderate**
band — the before/after this remediation demonstrates is the Phase 7 deliverable.
